# photo-blog-app

Application code for Seungwan's Photo Blog: a Next.js web app, a FastAPI API and Postgres with pgvector.

Docker, Kubernetes and AWS setup are maintained separately (`photo-blog-gitops`, `photo-blog-infra`).

## Layout

```
apps/
  web/   Next.js (App Router, TypeScript)
  api/   FastAPI (Python)
    app/models/     SQLAlchemy tables
    migrations/     Alembic migrations
```

## Run locally

Needs a Postgres 16+ with pgvector available (for example the `pgvector/pgvector:pg17` image) on `localhost:5432`.

**API**

```bash
cd apps/api
python3 -m venv .venv && source .venv/bin/activate   # first time only
pip install -e '.[dev]'                               # again after dependencies change
alembic upgrade head                                  # apply database migrations
uvicorn app.main:app --reload --port 8000
```

**Web**

```bash
cd apps/web
npm install
npm run dev
```

| URL | What |
|---|---|
| http://localhost:3000 | Website with a system check |
| http://localhost:8000/docs | API docs, generated by FastAPI |
| http://localhost:8000/health/ready | Database and pgvector check |

## Configuration

| Variable | Used by | Default |
|---|---|---|
| `DATABASE_URL` | api, migrations | `postgresql+psycopg://photoblog:photoblog@localhost:5432/photoblog` |
| `API_INTERNAL_URL` | web (server side) | `http://localhost:8000` |

## Migrations

```bash
cd apps/api
alembic upgrade head        # apply all
alembic downgrade -1        # undo the last one
alembic current             # show the applied revision
alembic upgrade head --sql  # print the SQL without running it
```

The first migration enables the `vector` extension, so the same migrations work on a local container and on RDS.
